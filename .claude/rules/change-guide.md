# Change guide: vida-platform

The stages every change here goes through, in order.

## 1. Read the governing docs

The owning ADR in docs/core/decisions/, the feature's five aspects under docs/features/<module>/ (identity · business-rules · contract · structure-data · conventions), any docs/modules/<module>/current-*.md, and the CLAUDE.md of every layer you touch. REPO.md maps where things live.

## 2. Trace the flow

Follow docs/core/architecture/data-flow.md from the UI read/write through the service, repository and encrypt seam; cross-module reads go through the shared foundation/views ViewProviderRegistry (docs/core/architecture/cross-module-integration.md).

## 3. Observe real state

`pnpm dev:app` for the local-first app (no server in M1). Live-store tests run over better-sqlite3; browser persistence uses the Playwright harness in apps/web/e2e (window.__vidaDb backdoor). Date code gets TZ-forced tests.

## 4. Where problems are written up

The Linear issue (team LIF); a decision that outlives the issue becomes an ADR in docs/core/decisions/; recurring failures in docs/core/known-failures.md. Never write session, status or decision-log files.

## 5. Plan

Slice plans live in docs/features/<module>/delivery/PLAN-S*.md; registering a service in apps/web/src/db/composition-root.ts happens in the entity's closing slice (docs/specs/foundation/golive-replan/process.md, Entity Live Close).

## 6. Landmines

App-wide write lock (BR-RT-LOCK): no nested db.transaction. React Query errored queries need retryOnMount:false on state-swapped surfaces. Editing @vida/types needs a dist rebuild before @vida/core typecheck. better-sqlite3 ABI vs Node. macOS 12 cannot run the Chromium e2e locally: rely on CI.

## 7. Validate

`pnpm check` (format:check + lint + typecheck + test + e2e); packages/core has no lint script, so run eslint from the repo root. UI changes also pass the Visual Gate in a real browser.

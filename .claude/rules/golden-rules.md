# Golden rules: vida-platform

Hold these in every change to this repo.

- Zero-knowledge: the server never sees plaintext. Never log, persist or transmit the Vault Key, Master Key or password; only opaque encrypted fields and SRP proofs leave packages/core/src/encryption.
- Column conventions: PK = UUIDv7 TEXT generated client-side; timestamps = Unix ms INTEGER; money = INTEGER cents; booleans = INTEGER 0/1; calendar dates = TEXT YYYY-MM-DD; JSON = stringified TEXT.
- Never add an inline `notes` column: notes live in `pages` via entity_type/entity_id.
- Every syncable table spreads `...baseColumns` and `...syncColumns` from schema/_shared.ts; never hand-repeat the `_sync_*` columns.
- Enums are `as const` tuples in @vida/types with the union type derived from the tuple; never a TS `enum` or a bare union. `z.enum(TUPLE)` in @vida/core and the SQL CHECK list are sourced from the tuple (enum-parity.test.ts enforces it).
- Soft deletes only: `deleted_at INTEGER` (NULL = live).
- Inside a `db.transaction` callback use only `tx` / `*InTx` APIs, never the outer `db` (nested lock → 30 s TransactionLockTimeoutError). Every write is transactional; never a bare insert/update/delete `.run()` outside a transaction.
- Migrations are hand-written SQL in packages/core/src/db/migrations, forward-only (no down()), registered in runner.ts ALL_MIGRATIONS; never edit a merged migration, add the next number.
- packages/core/src/db/_legacy, docs/_legacy and Old/ are quarantined reference-only code: never import or extend them.
- ADR-001 … ADR-017 in docs/core/decisions/ govern; a downstream shape never reopens an ADR.
- packages/ui/src/themes/{tokens,themes,fonts,motion,shadow}.ts are generated by build-tokens.mjs: change the source and rebuild, never hand-edit.
- apps/web never registers a `beforeunload` listener (cancelable → a live page with a dead worker); teardown is pagehide/pageshow in db/boot.ts.
- Never `pnpm rebuild` better-sqlite3: its ABI must match the running Node.
- Services follow docs/core/architecture/data-flow.md (validate → repository → encrypt-seam → return) and ride packages/core/src/foundation substrates; never re-implement a substrate inside a module.
- Branch `lif-<id>-<slug>`, PR description includes `Fixes LIF-<id>`, conventional commits (feat:/fix:/refactor:).

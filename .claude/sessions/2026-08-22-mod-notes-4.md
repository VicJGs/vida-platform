## Accomplished
- **Bug #1 — vault-not-initialized-on-boot (FIXED + verified live in Brave).** ⌘K→"New note" threw `Vault not
  initialized — call initVault() first` (swallowed by `commands.ts`'s no-log catch). Root cause: `apps/web` never called
  `initVault()` at boot; every repository WRITE computes a **keyless** `_sync_hash` via `hashContent()→assertReady()`
  needing libsodium loaded — INDEPENDENT of `[E]` field encryption. The Step-0 baseline finding #6 was half-wrong: it

  independent subagents** — docs-grounding (ADR-017 permits keyless M1.0 writes; onboarding forbidden from vault-creation;
  boot is the documented startup owner), adversarial critique (resolved the make-or-break: `computeSyncHash` runs
  MAIN-thread, not in the worker → main-thread `initVault` fixes it), and preflight (scope = platform-wide; the mock
  blind spot that let 218 tests pass). Fix: `apps/web/src/db/boot.ts` (`Promise.all([initVault(), c.open()])`) +
  `commands.ts` (log the discarded error) + new `apps/web/src/db/boot.test.ts`.
- **Bug #2 — editor-empty-doc-assert-crash (FIXED + verified live).** Found while verifying #1: opening a NEW note crashed

  null content → `safeParse(null)` seeds an empty doc. Ran `/victor-triage` (ISOLATED). Fix: normalize missing
  `content→[]` in `packages/editor/src/editor.tsx` + TDD regression tests (corrected editor.test.tsx:121 which had

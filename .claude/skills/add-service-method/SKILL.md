# Add or change a method on a @vida/core module service.

## Inputs

- the BR ids from docs/features/<module>/business-rules.md or current-business-rules.md
- the slice PLAN
- the foundation substrates it rides

If an input is missing, ask; never guess.

## Rules for this operation

- Services follow docs/core/architecture/data-flow.md (validate → repository → encrypt-seam → return) and ride packages/core/src/foundation substrates; never re-implement a substrate inside a module.
- Inside a `db.transaction` callback use only `tx` / `*InTx` APIs, never the outer `db` (nested lock → 30 s TransactionLockTimeoutError). Every write is transactional; never a bare insert/update/delete `.run()` outside a transaction.
- Soft deletes only: `deleted_at INTEGER` (NULL = live).

## Steps

1. Read the module's CLAUDE.md, its current-spec/business-rules docs and the substrates' CLAUDE.md under packages/core/src/foundation.
2. Write the failing better-sqlite3 live-store test named after the BR.
3. Implement in the factory-object service (no `this.` for intra-calls): Zod-validate input, write via repository inside a transaction, return the domain shape.
4. Fan out effects/measurement through the foundation rails, best-effort side effects in their own try/catch after the durable write.
5. Update the module CLAUDE.md status and the current-* docs.
6. Run `pnpm check` (eslint from the repo root for packages/core).

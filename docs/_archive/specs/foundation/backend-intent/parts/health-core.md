# Backend Intent — Part A: health-core

> Module: health-core (special-sources module · **recovered domain** — planned in v1, never built, absent from v2: NO schema, NO `@vida/types`, NO service; every token is `[INTENT]` with NO As-is FACT floor — intake.md:9-11; structure-data.md:4-12,6). Health/Core is the **shared spine** both Health pillars (Training, Nutrition) act on — the body's state (Metrics + Monitoring), its direction (Goals), its adaptation (Experiments/Profiles), its Physical Roles, Safety & Medical, plus the energy bridge (identity.md:4-11). It is a **heavy measurability owner** (goals derive from metrics; role mastery derives from exercises/goals) and the framework's **heavy external-surface owner** (wearable/Google-Health INPUT + the uniquely-named **medical-services OUTPUT egress**). Sources read: `docs/features/health/core/{identity,structure-data,business-rules,contract,conventions}.md` (S1) · `docs/intake/health.md` (S2 — the special source, forks 1-4 + CI-1..CI-6 + HL closing resolutions) · `docs/roadmap/m1.1-delivery-plan.md` §9 (S3 — **no MOD-health bucket exists**; Health is an M1.3-Depth module, delivery-table:154) · `docs/specs/foundation/realignment-master-plan/part-1.2-reruns/health-core.md` (S4 — ✅ IMPLEMENTED 2026-07-24, LITE gate SHIP) · service stub (S7 — `packages/core/src/services/health/` **does not exist**).
>
> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row (P6). Health/Core is a genuine service-heavy spine (7 designed services: Metric/Monitoring/Exam/Goal/Experiment/Physical-Role/Medical — contract.md:9-30) with heavy derivations (goal `progress()`, role `deriveMastery()` weighted rollup, derived metrics BMR/BEE/LBM/body-fat-mass/1RM, energy-loop recompute, safety-flag raising) + the M5 measure read seam + X*/AI* extension seams (forward-dep stubs). All view surfaces (metric series charts, monitoring dashboards, goal/role/experiment/medical UIs, safety-flag surfacing) are UI (P6). The `@vida/core` health services do **NOT** exist — every service row below is DESIGNED interface (contract.md:6-8 "Designed interface — not yet coded"), authored at the health build phase (ADR-016/017).
>
> Cross-cutting: goal/role measurability rides the ADR-011 M1/M2/M3/M4/M5 vocabulary + `contributions` up-ladder (Purpose-owned) + the M5 `measure(name,range)`/R7 read seam (Health is the PROVIDER, Purposes PG6 + `derived-pull` goals are readers); tags ride ADR-006 `entity_tags`/open registry (Spaces-owned); external INPUT rides ADR-014 X1/X2/X5/X8 device-mediated ingestion; **medical OUTPUT rides ADR-014 X4 egress** (`external_out_ok` + union-of-consents + audit + never-auto-transmit — Health CI-6 is ADR-014's NAMED egress example); AI plan/meal/role/photo rides ADR-015 AI1/AI3/AI5/AI6 (`source=ai`); workout runtime rides ADR-004 Sessions (`workout` sub-type); XP feed rides the Sessions S4 effect layer (C3 guard — Health does NOT own the ledger); scheduling rides `dueIn()`; notes ride Notes `pages`; protocols live in Knowledge. Health names the contracts it rides; it does not author them.

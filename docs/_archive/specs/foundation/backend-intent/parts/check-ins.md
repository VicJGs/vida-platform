> Module: check-ins (standard module · Wave 1 independent domain — feeds Journal `/summary` + mood/energy trends + Gamification). Sources read: `docs/features/check-ins/{identity,structure-data,business-rules,contract,conventions}.md` (S1) · `docs/intake/check-ins.md` (S2) · `docs/roadmap/m1.1-delivery-plan.md` §9 MOD-checkins (S3) · `docs/specs/foundation/realignment-master-plan/part-1.2-reruns/check-ins.md` (S4) · `packages/core/src/services/checkins/CLAUDE.md` (S7).
>
> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row. Check-ins is a genuine service module — CRUD + a template form-engine + a derived streak + trend datasets + a cross-module review aggregator. The entry-wizard/history/calendar/dashboard/template-builder chrome are UI (P6); the DERIVATIONS behind them (streak, trend datasets, active-template resolution, review aggregation) are service.
>
> Zero-code note: there is NO `@vida/types` check-in file and NO `@vida/core` model/service (only ADR-002 §5.13 schema + a 16-line directory-home `CLAUDE.md`). Every signature below is the DESIGNED interface to be built at MOD-checkins ① (S3). Schema CK-2/CK-3 fixes are ALREADY in DB-4 (`026_check_ins.ts`) — verify, don't re-author.

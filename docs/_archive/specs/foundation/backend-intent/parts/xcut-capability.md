# Backend Intent — Part A: xcut-capability

> Cross-cutting source: **ADR-008** (open capability/block registry — a capability declares its render targets;
> placement is the user's choice) + **ADR-010** (user-authored capabilities run under a declare→grant→enforce
> permission envelope inside a no-ambient-authority sandbox) + **`docs/core/capability/current-spec.md`** +
> **`docs/core/capability/current-business-rules.md`** (the AS-BUILT substrate promoted from AR-7 Increment 2 /
> §XXIX) + the built seam
> (`packages/core/src/foundation/capability/{registry,types}.ts`, migration 005) + the framework rows
> (`capability-framework.md` §3 CB1–CB6 · A1–A9). Related ADRs: ADR-004 (the permission envelope SS-6 + write-API
> contract §3.2.5 this reuses), ADR-005 (the 6-part anatomy + `study_methods` as `kind=study_method`), ADR-006
> (a capability is a taggable/note-linkable Spaces citizen; `space_enabled_blocks.capability_def_id` is the palette
> seam — homed in **xcut-spaces**), ADR-009 (imported-template caps = untrusted), ADR-014/ADR-015 (external-data /
> AI actor amendments to the envelope).
>
> **Boundary of this part.** The **registry** (CB1–CB6 structure + validation) is **AS-BUILT** (`CapabilityRegistry`
> service exists — register/get/list + BR-2..6). The **authoring-security runtime** (A1–A9 sandbox / grant
> enforce/re-grant/revoke / mediated capability API) is **DEFERRED → `#85 CAP-authoring`** but its INVARIANTS are
> locked NOW (ADR-010 §3 "locks the invariants any of those must satisfy") — so every A-row is a real service-intent
> item with a fixed contract, homed here even though its runtime is a later increment. The **registry runtime**
> (block placement · inline instances · TipTap re-home · per-Block visual) is DEFERRED → MOD-notes `#31` / UI-3 `#29`.
> Every row is an ENGINE / cross-cutting foundation concern (a capability is authored by every module + editor + ui).
> Final homing is P3.
>
> **Cross-part note.** `space_enabled_blocks` (the offered-palette junction) is owned by **xcut-spaces**
> (XCU-SP-09/XCU-SP-29); `block_instances` (standalone placements) STRUCTURE is registry-owned (below) but the
> placement-creation SERVICE is deferred to MOD-notes/UI-3. Effect FIRING (declared effects → real writes) is owned
> by the effect rail — see **xcut-sessions**; this part covers only effect **declaration/validation** at register-time.

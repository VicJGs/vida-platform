# Backend Intent — Part A: books

> Module: books (standard module · M1.2 Feature Module — extracted from Learning 2026-07-03 as its OWN module, B1–B16). The OS's **reading Universe**: the reading **plan** (what/at-what-pace/by-when) + the reading **experience** (read/listen in-app across every format) + everything captured (highlights, bookmarks, quotes, notes, photos, sessions, statistics), with a **partition serving Learning** (Books↔Education). Sources read: `docs/features/books/{identity,structure-data,business-rules,contract,conventions}.md` (S1) · `docs/intake/books.md` (S2 — intake "whole", B1–B16 all resolved) · `docs/roadmap/m1.1-delivery-plan.md` §9 (S3 — **NO books bucket exists in §9**; books is an **M1.2 Feature Module** forward-declared at delivery-plan:153-155, "earns its own delivery plan at its gate"; §9 covers only the 6 M1.1 modules) · `docs/specs/foundation/realignment-master-plan/part-1.2-reruns/books.md` (S4 — ✅ IMPLEMENTED across all 5 aspects, re-verified by the Part-1 EXIT gate 2026-07-25; a **MIXED case**: 2 live-FACT R6 reframes + an S1 reframe + X*/AI* layering) · `packages/core/src/services/books/CLAUDE.md` (S7 — **does not exist**; no directory-home stub).
>
> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row (P6). Books is a genuinely service-heavy module (unified-progress DERIVATION under a conflict rule · cross-format position mapping · adaptive quota planning + recalculation · pace-status derivation vs Education schedule · reading-session composition on Sessions · ISBN ingest + OCR/TTS/transcription AI pipelines · quote-embed feed · conflict-resolution engine). The whole surface — Reading Hub, Bookshelf/All Books (gallery|list|table), All Plans + per-plan, All Quotes library, Book Hub tabs, the in-app Reader (read/listen/annotate), Physical companion mode, the Add-Book/Plan wizards, conflict prompts — is UI (P6). The `@vida/core` books service tier does **NOT** exist yet: `models/learning.ts` = 0 lines, `services/study-planner.ts` = 0 lines, no service CLAUDE.md; only `Book` + `BookChapter` FACT-base types exist in `@vida/types/learning.ts` (contract.md:5-8; intake.md:24-25). **Every service row beyond FACT-base CRUD is DESIGNED interface** (⚠ INTENDED), authored at the books build phase (ADR-016/017, M1.2).
>
> Cross-cutting: books is a **cite-not-re-spec composer**. It rides — never authors — the ADR-004 Sessions `reading` sub-type + shared timer/scheduling (base owns lifecycle; Books adds only the 1:1 extension columns), the ADR-006 `entity_tags` primitive (publisher/genre/category), the ADR-011 M1/M2 pursuable measurement axes (the reading-plan goal is a target; unified progress is quantitative/derived-pull) + M3 nullable-override, the Notes `pages`/`entity_links` seams (bookmark/quote notes + new annotation entity types) + the `@vida/editor` quote-embed block, the R2 attachment pipeline (encrypted files + page photos), the ADR-014 external-ingestion X-family (ISBN lookup = X1/X2-public-reference/X3/X5/X9) + ADR-015 AI layer (OCR/TTS/transcription = X11 → AI1/AI3/AI5/AI6), the Preferences store (quote-embed toggles, conflict rule, reader/companion defaults), the Education contract (partition reads `subject_schedules`/assessment dates). **No E2** — Books is NOT an economy feeder (rerun C-E2); reading grants ride the base-`sessions` sub-type, not Books. **No AI4** agent envelope (rerun C-AI4) — OCR/TTS/transcription are scoped model calls. As-is FACT floor = 2 live tables (`books` `schema.ts:641` with two live anti-signals — inline `tags` `[E]` `:657` [→ `entity_tags`, SP1] + `progress NOT NULL DEFAULT 0` `:650` [→ nullable-override, M3]; `book_chapters` `:661`). The entire INTENDED entity family (assets, 3 annotation types, reading sessions, plans, `book_subjects`, mapping/anchor data, conflict state) is the 2nd-largest ADR-002 amendment (after Education) — **DDL + schema reconciliation `[DEFERRED — build phase, ADR-016]`**; this campaign homes the SERVICE intent only.

> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row (P6). >
> Cross-cutting (Purpose is the **rollup APEX + primary consumer**, NOT the owner, of the measurability contract): the ADR-011 `measurement_kind`/`binding_mode`/`progress()` vocabulary lands on EVERY pursuable module (Tasks·Habits·Routines·Projects·Dreams·Health·Finance) — Purpose consumes + rolls up (PG-3 business-rules.md:26-29). The **measurement-source READ seam** (Finance net-worth · Habits streak · Health body-weight · Projects milestone-%) is INT-1-respecting and shared. The **`contributions` weighted-laddering edge** is Purpose-DOMAIN machinery (NOT a Spaces universal primitive — INT-1a owns `entity_links`+`entity_tags`), yet its contributor set spans 7 modules. `event-trigger` bindings ride the shared **INT-2 effect rail** (`effect_event_id`, ADR-004 §3.2.5) — no new engine. Reviews fire as **`review` SESSIONS** (ADR-004 sub-type) on the shared Scheduler/`dueIn` seam. Purpose **registers as a provider** (`summary(date)`/`dueIn(range)`) into Journals + Global Calendar. Notes via `pages`, tags via Spaces `entity_tags`, XP feed via Gamification. Purpose NAMES the contracts it rides; it authors only `contributions` + its own `progress()` implementation + the rollup.

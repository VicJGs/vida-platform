# Backend Intent — Part A: tasks

> Module: tasks (standard module · Wave 1 — first independent domain, but an AGGREGATOR that fans out to 4 parent modules). Sources read: `docs/features/tasks/{identity,structure-data,business-rules,contract,conventions}.md` (S1) · `docs/intake/tasks.md` (S2) · `docs/roadmap/m1.1-delivery-plan.md` §9 (S3 — **no MOD-tasks bucket exists**; §9 lists only the M1.1 wave; tasks is an M1.2 module per delivery-table:153 and appears in §9 only as a *consumer/contributor* of other modules) · `docs/specs/foundation/realignment-master-plan/part-1.2-reruns/tasks.md` (S4) · `packages/core/src/services/tasks/CLAUDE.md` (S7 — directory-home stub only, no logic).
>
> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row. Tasks is a genuine service-heavy module (CRUD + aggregation + rollup + effect production + timer/session); the 12 layouts, view-builder chrome, board drag, running-timer indicator, and optimistic apply/revert are UI (P6). The `@vida/core` task services do **NOT** exist yet (contract.md:6) — every service row below is DESIGNED interface, authored at the tasks build phase (ADR-016/017).
>
> Cross-cutting: every effect-producing item rides the ADR-004 S4 catalogue / R1/R2 rails (Sessions-owned), the ADR-012 economy feeder (Gamification-owned), the ADR-006 `entity_tags` primitive (Spaces-owned), the ADR-007 `views` primitive (Views/Spaces-owned), the ADR-011 `contributions` ladder (Purpose-owned). Tasks names the contracts it rides; it does not author them.

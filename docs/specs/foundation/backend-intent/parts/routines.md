# Backend Intent — Part A: routines

> Module: routines (standard module · M1.2 feature module · delivery-table:153 — an ORCHESTRATION cockpit that COMPOSES steps driving entities in Sessions/Tasks/Habits/Health/Knowledge, and REGISTERS as a `dueIn`/`summary` provider). Sources read: `docs/features/routines/{identity,structure-data,business-rules,contract,conventions}.md` (S1) · `docs/intake/routines.md` (S2) · `docs/roadmap/m1.1-delivery-plan.md` §9 (S3 — **no MOD-routines bucket exists**; §9 lists only the M1.1 wave [notes/prefs/journals/… delivery-plan:185+], and routines is an M1.2 module per delivery-table:153, appearing in §9 only implicitly as a consumer/provider) · `docs/specs/foundation/realignment-master-plan/part-1.2-reruns/routines.md` (S4 — ✅ IMPLEMENTED, driver-token pass 011/012/006) · `packages/core/src/services/routines/CLAUDE.md` (S7 — directory-home stub only, no logic).
>
> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row (P6). Routines is a genuine service-heavy module (routine/step CRUD + policy-evaluation derivation + streak/analytics recompute-from-ledger + provider seam + effect emission). The today-list grouping chrome, per-step live-entity render, standalone-page analytics render, drag-reorder, and the alarm/timeframe surface are UI (P6). The `@vida/core` routine services do **NOT** exist yet (contract.md:6 "v2 code is schema-only, 0 service logic"; service CLAUDE.md:14-16) — every service row below is DESIGNED interface, authored at the routines build phase (ADR-016/017).
>
> As-is FACT floor (2 tables, schema-only POC): `routine_actions` + `routine_completions` (structure-data.md:7-13; schema.ts routine_actions:297, routine_completions:316, purpose_routines:421 per rerun:8). The INTENDED reframe (`routines` + `routine_step` + `routine_step_membership` named-ordered-sequence + policy/lifecycle + pursuable axes) LANDED 2026-07-14 §E (rerun §1:15) and is the intent authority.
>
> Cross-cutting: Routines COMPOSES and names contracts it does NOT author — the ADR-004 Session sub-type registry + Scheduler `dueIn`/availability (Sessions-owned), the ADR-011 `contributions` ladder + measurability axes (Purpose/measurement-owned), the ADR-012 `grant_currency`→`consequence_ledger` economy feeder (Gamification-owned), the ADR-006 `entity_tags` primitive (Spaces-owned), the ADR-007 `views` saved-view primitive (Views/Spaces-owned), the Notes `pages`/`entity_links` polymorphic seam (Notes-owned), the Journals provider registry (`summary(date)`). **Routines never writes a parallel completion, never writes XP, never owns a scheduler/session-engine/tag-store/purpose-metric** (identity.md:39-59; conventions.md:32-46).

# Backend Intent — Part A: skills

> Module: skills (standard module · Wave R — recovered/reframe; higher-order/cross-cutting like Purposes). A **game-like growth engine producing real-life outcomes**: user-**composed** cross-domain capabilities with a per-skill configurable progression ladder, developed through activities that **dispatch to the real OS modules**, tracked with **derived** mastery, connected in a dependency **Skill Graph**. Sources read: `docs/features/skills/{identity,structure-data,business-rules,contract,conventions}.md` (S1) · `docs/intake/skills.md` (S2) · `docs/roadmap/m1.1-delivery-plan.md` §9 (S3 — **NO skills bucket exists in §9**; skills is an **M1.3 Depth** module that "earns its own delivery plan at its gate" per delivery-plan:154; §9 covers only M1.1) · `docs/specs/foundation/realignment-master-plan/part-1.2-reruns/skills.md` (S4 — ✅ IMPLEMENTED across all 5 aspects, re-verified by the Part-1 EXIT gate 2026-07-25; the **first X*/AI* unit** in the campaign) · `packages/core/src/services/skills/CLAUDE.md` (S7 — **does not exist**; no directory-home stub).
>
> Boundary note (ADR-020): items with both a derivation/logic face and a state/render face are SPLIT into a service row + a UI row (P6). Skills is a genuinely service-heavy module (Composer definition/integration recipe · configurable-ladder gate evaluation · **derived** mastery/level/progress · dispatch-orchestration · practice-as-Sessions composition · Skill-Graph path-recommendation/synergy-detection · SRS decay · external Skill-DB ingest + AI-draft). The whole editor/config surface — the **Skill Composer Quick/Advanced UI**, the **Life Skill Tree** neural-graph render, the **"Becoming" identity view**, the standalone Skill Space, dev-log entry forms — is UI (P6). The `@vida/core` skills service tier does **NOT** exist yet (contract.md:6 "Designed — not yet coded"; no service CLAUDE.md) — **every service row below is DESIGNED interface**, authored at the skills build phase (ADR-016/017, M1.3).
>
> Cross-cutting: skills is a **cite-not-re-spec composer**. It rides — never authors — the ADR-004 Sessions `practice` sub-type + `dueIn` scheduler, the **reflective/Adaptation engine SHARED with Health**, the Knowledge compound-set / review-curve (SRS), the Purposes Target-Mastery `contributions`/M1/M2 target-ownership, the ADR-012 economy feeder `grant_currency(XP)`/`consequence_ledger`, the ADR-006 `entity_tags` primitive, the Notes `pages`/`entity_links` seams, the ADR-014 external-ingestion X-family (`external_in_ok`/`external_out_ok`, `import_staging`) + ADR-015 AI layer (`ai_connections`, `on_device`/`cloud` modes). As-is FACT floor = 2 live tables (`skills` `schema.ts:677`, `skill_resources` `:689` with a narrow `resource_type` CHECK('course','book') to be retired → `entity_links`). Per S4 §1 this is a **PURE additive** reframe: zero forward retired tokens (no R6 two-tier); the one retirement (`skill_resources`→`entity_links`) is already in-doc (verify-only).

# Backend Intent — Part A: xcut-backlinks-search-export

> Cross-cutting source: the AR-8 **foundation read/query services** — the READ side of the platform's
> connective tissue. Four engines live here:
> 1. **Backlink resolver** (BUILT, AR-8 #1) — `packages/core/src/services/search/backlink-resolver.ts` +
>    `docs/core/backlinks/current-spec.md` + `current-business-rules.md` (BL-1..BL-6). The read/resolve half
>    of the `[[wiki-link]]` system over the AR-6 `entity_links` substrate; NEVER mutates.
> 2. **FTS5 full-text search** (DEFERRED — DB-8/M1.4) — `services/search/CLAUDE.md:8` + ADR-002 §5.19 +
>    `performance-strategy.md §4` + `command-bar-and-search.md` (the `SearchProvider` seam + result/terminal
>    contract UX-2 fixes). The engine every searchable module's Part-A row points at (notes NOT-50,
>    knowledge KNO-37, learning LEA-70 all route "→ Part B search/FTS5").
> 3. **Export serializers** (DEFERRED — UI-3 `@vida/editor` / per-feature build) — `services/export/CLAUDE.md`
>    + ADR-001 L100-102 (MD round-trip · @react-pdf/renderer web · expo-print mobile · docx). Markdown/PDF/DOCX
>    export of notes/journals.
> 4. **Neural-graph data-prep** (DEFERRED — AR-8 increment #2 / Views design-pass) — `services/search/CLAUDE.md:9`
>    + `docs/core/spaces/current-spec.md:33` + notes NOT-49. Force-directed nodes/edges built from
>    `page_links` ∪ `entity_links`.
>
> This part also frames the **R7 read-seam FAMILY** (`summary(date)` / `dueIn(range)` / `measure(name,range)`)
> as the one shared read-contract pattern (INT-1) — but does NOT re-home the owning engines: `dueIn` is
> Sessions-owned (SES-19/20/21), `summary(date)` is Journals-owned (JOU-01/02), the ViewProviderRegistry is
> Views-owned (xcut-views XCU-07/08), the measurement source seam is Measurement-owned (xcut-measurement
> XCU-06/07). Those rows are cross-referenced, not duplicated (§4c dedup: the read-seam PATTERN is the Part-B
> concern; each concrete engine stays in its owner's Part A).
>
> Boundary note (ADR-020): the backlink RESOLVER is a pure read service (no state face). Search + export +
> graph-prep each SPLIT into a service row (index/query/serialize/data-prep derivation) + a UI row (search box,
> export dialog, Sigma.js render → P6). Every row's final home is P3.

# Backend Intent — Part A: xcut-notifications

> **Context:** cross-cutting **notification DELIVERY** engine — the zero-knowledge three-tier delivery
> contract. Owning ADR: **ADR-013** (ZK notification delivery). This xcut source owns **how a notification
> reaches the user off-device without the server reading it** — the delivery *mechanism*, NOT the notification
> records / dispatch policy / gating (those are **MOD-notifications**, a separate Part A) nor *what/when* is
> due (Notifications dispatcher + Sessions `dueIn`). `[FACT: ADR-013 §3.6 L69-74 ownership boundaries]`
> **Substrate status:** greenfield / **UNBUILT** — the Hono server has `auth`/`sync`/`billing` routes and
> **no notification route**; `reminder-engine.ts` = 0 bytes; this is a structural decision, not a migration.
> `[FACT: ADR-013 §2 L35 grep-clean; NF business-rules:7]`
> **Ownership rule (the delivery boundary — ADR-013 §3.6):** ADR-013 OWNS the three-tier delivery contract ·
> the content-minimal push payload spec · the per-channel ZK-fidelity rule (in-app full · push wake-only ·
> email generic · no-SMS) · the **wake-relay** capability · the metadata bound · the push-token registration
> seam (columns on ADR-003's device registry, existing `/api/devices/register`). It does NOT own the
> `notifications` records, dispatch/gating, quiet-hours/channel *config* (Preferences §5.17), or `dueIn`
> (Sessions). It **extends** ADR-003 (adds a wake-relay server responsibility + 2 device-registry columns),
> it does not fork it. `[FACT: ADR-013 §3.6 L69-74; Amends L8-11]`
> **Cross-plane by nature:** every row here has ≥2 contributors — the delivery engine composes
> **MOD-notifications** (the dispatcher/records), **Sessions** (`dueIn`), **Preferences** (quiet-hours /
> channel toggles), **Sync/ADR-003** (relay, device registry, per-user rooms), and the **platform layer**
> (Expo/Tauri/Web-Push/service-worker per ADR-001). `[FACT: ADR-013 Inherits L12; §3.6]`
> **Provisional homes** name a **notification-delivery service (ADR-013, `@vida/core` platform-delivery
> tier)** for the client-side dispatcher/scheduler legs, and the **server wake-relay (Hono)** for the
> server leg. Final homing is P3.

## UNKNOWNs

- **Rich / actionable push (buttons, images)** — ⚠ INTENDED-later (ADR-013 §3.6 L76). The locked contract is content-minimal (XCU-08); rich push would need a non-content-free payload and is explicitly out of the ZK core (§6 L119(d): "change vendor, not the contract"). Blocker: conflicts with the content-zero bound; only via an explicit opt-in "readable push" mode outside ZK (EX-1/EX-2 guarded-extension). Resolution owner = ADR-013 review (Victor). Resolve-by: post-M1, only if users demand it. Not homed to a build row — genuinely deferred.
- **Notification-history server backup** — ⚠ INTENDED-later (ADR-013 §3.6 L76). Would add a server-side surface beyond the blind relay. Blocker: tension with ZK (server holds only opaque blobs today; a history backup is already covered by blob sync, so scope is unclear). Resolution owner = ADR-013 / ADR-003 review. Resolve-by: post-M1. Not homed to a build row.
- **Digest / batching delivery (N5)** — ⚠ INTENDED-immature (ADR-013 §3.6 L76; intake N5:76-77). `notification_frequency` (realtime/daily/weekly) grouping N reminders into one digest. Blocker: owes `notification_frequency` → Preferences §5.17 + a batching design-pass; not v1. Resolution owner = MOD-notifications + Preferences build. Resolve-by: post-M1 / notifications design-pass. Noted (delivery would gain a coalescing leg over XCU-01/XCU-06) — not built.
- **Push vendor + runtime policy (all build-phase, owed to ADR-002 §5.20)** — Expo vs OneSignal vs raw APNs/FCM; silent-push retry/coalescing; local-scheduler reschedule debounce; push-token exact columns/rotation; email provider (ADR-013 §3.6 L76; §5 L111-115). Blocker: the *contract* (content-free tiers + ZK bound) is locked; the *runtime* is deliberately open. Resolution owner = the Phase-6.7 mobile-push build session / ADR-002 §5.20 consolidation. Resolve-by: P2 schema-reconcile (device-registry + delivery-audit columns) / M1.x platform-delivery build. Homed to XCU-03/04/07/08/09/13/14 as contract intent — DDL/vendor deferred, intent captured.
- **Silent-vs-visible closed-device wake reliability** — the silent `content-available` path is throttled/best-effort on killed iOS; the fallback is a generic visible banner (XCU-09). Blocker: exact retry/coalescing + per-platform behavior is build-phase and platform-dependent (review trigger §6 L119(a): a platform removing reliable local scheduling → lean harder on wake-signal). Resolution owner = platform-delivery build + ADR-013 review. Resolve-by: Phase-6.7 build. Homed to XCU-09 (contract) — runtime deferred.

## §1. Context — why this re-run, and the true stale shape

It predates ADR-011 (measurability), ADR-012 (economy), ADR-006 (tags), ADR-007 (saved views), ADR-009 (presets), and the ADR-004 effect rails. Sweep verdict is **stale**: it names **`task_views`** + **`page_tags`** as forward build targets, and is silent on `measurement_kind`/`binding_mode` (M1/M2), `grant_currency` (E2), and presets (T4).

**The R6 fact that shapes this unit (a *mixed* live/intent floor):** tasks **HAS a live v2 schema** (grepped: `tasks` `schema.ts:161`, `task_time_logs` `:189`, inline `tasks.tags` `[E]` TEXT `:176`, `page_tags` `:121`). So the tag retirement rides a **real As-is FACT floor** (like habits/finance). BUT the two heaviest forward tokens diverge on floor-status:
- **`page_tags`** — a live FACT (`schema.ts:121`, notes domain) that the tasks doc names **forward** → retire in `[INTENT]`.
- **inline `tasks.tags`** — a live FACT (`schema.ts:176`) → As-is floor, retired in `[INTENT]`.
- **`task_views`** — **schema-0** (does NOT exist in `schema.ts`; grep-confirmed absent) — it is an **`[INTENT]` build target**, not a live table. So V1 **reframes an `[INTENT]` token in place** (no As-is floor to preserve), distinct from the SP1 live-FACT retirement.

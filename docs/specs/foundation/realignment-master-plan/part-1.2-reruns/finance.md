## §1. Context — why this re-run, and the true stale shape

Finance is the platform's **private financial command center** — a **Wave-1 independent domain** with **6 live tables** (`accounts`, `transactions`, `assets`, `liabilities`, `investments`, `income_streams`), a derived-balance ledger model, and three cross-cutting edges the current docs express in **pre-framework terms**: it is **tagged**, it **owns economy substrate** (the money `store` + the `move_money` Additive effect), and it **ingests external data** (CSV/OFX). It predates ADR-006 (Spaces/tags), ADR-012 (economy), and ADR-014 (untrusted ingestion) — so all three edges name retired/unnamed tokens. Sweep verdict is **stale**: `page_tags` is named forward, the `store`/`move_money` substrate Finance OWNS is never named, and ingestion is framed as a "candidate ADR that *blocks* import" when ADR-014 already governs the mechanism.

**The R6 fact that shapes this unit (same as habits/projects — REAL As-is floor):** finance **HAS a live v2 schema** (grepped this session): `accounts` `schema.ts:447`, `transactions` `:462` (inline `tags` `[E]` `:475`), `assets` `:482`, `liabilities` `:494`, `investments` `:507`, `income_streams` `:519`; and **`page_tags` `:121`**. So the SP1 retirement is a **genuine As-is FACT floor** → recorded, then retired in `[INTENT]` (R6 two-tier). This is NOT the floor-less health/core case. Everything else (`store`, `move_money`, `import_staging`) is a **pure gap-add** — no floor to preserve (schema grep: `store`/`move_money`/`import_staging`/`node_kind`/`is_locked`/`dream_id` all **0** in `schema.ts`+`001_initial.ts`; every `store` string in the finance *docs* is prose — "money stores"/"FX-rate store" — never the E6 table).

**Ground-truth refinement (the sweep scored only structure-data; this PLAN reads all 5 aspects + the schema):** the stale tokens thread through multiple aspects, and the reframe is a **one retirement + one reframe + two economy gap-adds + ingestion-token naming** mixed case.

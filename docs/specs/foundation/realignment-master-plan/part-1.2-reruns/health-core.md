## §1. Context — why this re-run, and the true stale shape

It predates ADR-011 (measurability), ADR-006 (Spaces/tags), ADR-014 (external ingestion), ADR-015 (AI) — so it expresses these in **bespoke, pre-framework terms**. Sweep verdict is **stale** (wrong-model on the measurability axis), plus gaps on tags/ingestion/AI.

**The one structural fact that makes this unit cleaner than `projects`:** Health is a **recovered domain with NO v2 schema** (identity L1; structure-data L1–2, L6 "All entities are **new** … no v2 schema → ADR-002 additions"). So **every token is already `[INTENT]`** — there is **no As-is FACT floor to preserve**. The projects unit had to two-tier `progress NOT NULL` + `purpose_projects` (live FACTs in `project.ts`); here there is nothing live. Every M-axis edit is a clean **in-place `[INTENT]` correction** (like projects' already-`[INTENT]` `measurement_type`, never like its live-FACT `progress`).

**Ground-truth refinement (the sweep scored only `structure-data.md`; this PLAN reads all 5 aspects):** the wrong-model goal-`type` token and the derived-but-unslotted `progress`/`mastery` framing thread through **every aspect**, so this is the **mixed case** (wrong-model reframes on M1/M2/M3 + additive gap-fills on M5/SP1/X\*/AI\*).

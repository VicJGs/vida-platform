## §2. Business Rules

- **BR-S2-1** — The barrel add is **additive, no API change** (`export * from './foundation/templates'`); collision-free
  (verified). Rebuild `@vida/core` dist before `@vida/web` consumes it [FACT: editing-vida-types-needs-dist-rebuild].
- **BR-S2-2** — **Do not reimplement instantiate/capture** — that execution is `@vida/core` S3–S5 (first-consumer-pull).
  #13 documents the consumption convention over the SHIPPED `TemplatesService` (list/get/create/delete) only.
- **BR-S2-3** — **fork-on-instantiate has no back-link** — an instance keeps no `template_id`; the convention must not
  imply a live link (IR-5). [FACT: ADR-009 §1]
- **BR-S2-4** — **`enabled_blocks` (palette) ≠ `block_instances` (placements)** — palette curation gates _adding_, never
  force-deletes placements (IR-3). [FACT: ADR-008:128-140]
- **BR-S2-5** — Type + convention only; no live hook/instantiation (IR-1/H4). Scope-STATE (#15) + Spaces page (#20) are
  out of scope.

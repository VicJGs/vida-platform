## A. Cross-domain reference pattern (the resolution that unblocks everything)
`[FACT: schema/foundation/{spaces,economy}.ts — grep: zero references() in foundation/]`
The substrate uses **no hard FK `references()`**. Every cross-entity ref is **plain `text()` + polymorphic
`entity_type`/`entity_id`** (or a named `*_id` TEXT), because target tables live in later milestones — e.g.
`entity_links.page_id` is *"plain TEXT, no FK (N&P is M1.1)"*; `consequence_ledger.currency_id` is *"→ currencies.code,
no FK"*. **Consequence for DB-3:** every "FK, CASCADE" in a structure-data doc (e.g. `purpose_reviews.purpose_id`)
becomes **plain TEXT, no hard REFERENCES**; CASCADE/relational intent is documented and enforced app-side later. This
means **all 11 tables author cleanly now, with zero dependency on any DB-4 table existing.** The migration-ordering
concern is dissolved by the codebase's own pattern.

All 11 tables are **syncable** (`...baseColumns` = id·created_at·updated_at·`_sync_*(6)`; `+ deleted_at` where soft-delete
applies) unless marked local-only. `_sync_field_ts` is **NOT** added here (DB-2/M4, platform-wide). `[FACT: database-layer/current-business-rules.md #5; db-2 row]`

## C. Session sub-type extensions — DECISION: defer all 6 to DB-4
`[FACT: ADR-004 §3.1 L48-50 — each extension "owned by its domain module"]` `reading_sessions`→Books · `class_sessions`→
Education · `workout_sessions`→Health · `work_sessions`→Tasks · `study_sessions`/`focus_sessions`→Sessions & Scheduling.
**Decision:** author **none** in DB-3. Every sub-type's owner is a DB-4 domain group (incl. Sessions & Scheduling, a
Stream (ii) domain); none has a substrate consumer in M1.0 — the `sessions` spine already carries the stable
`session_id` they key off. Authoring them now would pull DB-4 domain shape into the substrate, violating Model B's own
grain. **Recorded, not dropped:** each lands with its domain group in DB-4. `[INTERP: ADR-004 domain-ownership is decisive]`

Each: Drizzle module in `schema/foundation/` + barrel export + registry append + Zod + tests. **[INTERP: grouping is gate-2's to finalize.]**

- `plan_steps` → `(owner_type, owner_id)`. · `purpose_reviews` → `(purpose_id)`. · `store` → `(parent_id)` (tree walk) + `(ref_type, ref_id)`.

- `values`/`templates` → PK-only (no polymorphic lookup). Gate 2 authors the exact `CREATE INDEX` DDL.

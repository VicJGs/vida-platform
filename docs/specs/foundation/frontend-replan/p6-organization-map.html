Frontend Re-plan · G1 · P6/F3 — The Organization (your vision)

How Vida is organized — built to your model.

Two positionable bars · Spaces as a global scope (not a strip) · a persistent Session HUD · pages as a Layout + Editor composition · and portability as a classic View vs a mixing Capability. Interact with each.

1

Navigation — two positionable bars, Spaces as a scope

Don't like a topbar + sidebar? Move them. Bar 1 = account · prefs · notifications · search · + the Spaces scope. Bar 2 = modules by default (or whatever you want). The Session HUD follows you. Try it:

Responsive panels, not fixed rails. Both bars are content-fitting panels (like a macOS/iPadOS inspector): they can dock together on any side, and take only enough room to show their contents — laid out in 2–3 columns or 1–4 rows, extending to the viewport edge only when they need to.
2

Composition — a Layout facet + an Editor facet

A page (normal or entity) follows one schema: Title · bio · summary · dashboard · views/content, built from blocks + widgets. Every entity can also carry an Editor (its linked page). You choose their relationship — merged into one surface, or tabbed (Home = the layout · Content = the editor).

Not "pages aren't editors." A note is an editor and a page (one entity). The Editor is a facet that page-able entity types can have (registry-gated, ADR-006 — many entities have none by default). Where it exists, you decide: merged in, or its own tab. Layout mode is also yours: free-reorder or tabbed sections.
